# jiro.bot

Static site for jiro.bot: a hand-written landing page (the marketing design with an early-access sign-up pop-up) plus generated comparison pages (alternatives, head-to-head comparisons, switching guides, best-of lists) for answer-engine optimization (AEO).
The landing page, copy editor and sign-up Lambda were consolidated here from the private `tilework-tech/jirobot-site` repo; archiving that source repo is pending approval. The previous interactive site work is preserved on the `backup/jiro-site-2026-10-09` branch (and `jiro-site`, which open PRs target).

| Path | What it is |
|---|---|
| `site/` | Everything published to jiro.bot, synced as-is. Hand-written: `index.html` with `css/`, `js/` (`main.js` page behavior, `features.js` tabbed “How it works” stories, `hero.js` hero carousel, `tabcycle.js` the autocycle timer both share, `jiro-pixels.js` pixel art, `early-access.js` pop-up), `fonts/`, `img/`, `video/`, and `confirmed.html`, `link-expired.html`, `privacy.html`. Generated and committed: `alternatives/`, `compare/`, `switch/`, `best/`, `assets/pages.css`, `llms*.txt`, `sitemap.xml`, `robots.txt`. Never put docs or other non-public files here |
| `content/` | TOML records the generated pages are built from, plus the content rules editors must follow. See [content/docs.md](content/docs.md) |
| `build.py` | Stdlib-only generator, `content/` -> `site/`. Owns one directory per page family under `site/` and rebuilds them from scratch; leaves hand-written files alone |
| `tools/` | Pre-publish lint, LLM grader, AEO probe, overlap check, AEO preview server. See [tools/docs.md](tools/docs.md) |
| `tools/copy-editor/` | Landing-page preview server with an optional inline copy editor. See [tools/copy-editor/docs.md](tools/copy-editor/docs.md) |
| `lambda/early-access/` | Sign-up and confirm Lambda. See [lambda/early-access/docs.md](lambda/early-access/docs.md) |
| `video/carousel-src/` | Sources and render scripts for the hero carousel videos in `site/video/carousel/`. See [video/carousel-src/README.md](video/carousel-src/README.md) |
| `aeo/` | Dated grader and probe results |
| `tests/` | Black-box tests of `build.py`, `tools/lint.py`, the `@Jiro` handle rule (`test_handle.py`) and the carousel video contract (`test_carousel_videos.py`, which needs ffmpeg: `npm ci` in `video/carousel-src/` provides `ffmpeg-static`; with `CI` set they fail instead of skipping); `tests/browser/` holds Playwright tests of the pop-up, hero and landing-page sections |
| `infra/site.cfn.yaml` | CloudFormation stack `jiro-bot-site` (S3, CloudFront, ACM, Route 53, deploy role) |
| `infra/early-access.cfn.yaml` | CloudFormation stack `jiro-bot-early-access` (SES identity, Lambda, HTTP API) |
| `.github/workflows/deploy.yml` | Manual-dispatch site deploy from `main` |
| `.github/workflows/deploy-early-access.yml` | Manual-dispatch Lambda code deploy from `main` |

Python 3.11+ (for `tomllib`) for the generator and tools; Node 22 for the Lambda and browser tests.

```bash
python3 tools/fetch_fonts.py         # fetch verified General Sans assets before previews/browser tests
python3 build.py                     # regenerate site/ from content/
python3 tools/lint.py                # must pass before publishing; also fails if site/ is stale
cd tests && python3 -m unittest      # generator, lint, handle and carousel video tests (video tests need ffmpeg)
python3 tools/serve.py               # preview all of site/ on :4310 with extensionless URLs
python3 tools/copy-editor/server.py --port 4100          # preview the landing page
python3 tools/copy-editor/server.py --port 4100 --edit   # ...with the inline copy editor

cd tests/browser && npm install && npm test              # pop-up, hero and landing-page browser tests (Playwright)
cd lambda/early-access && npm install && npm test        # Lambda tests (no network)
python3 -m unittest discover -s tools/copy-editor/editor -p 'test_*.py'   # copy-editor HTTP tests
node tools/copy-editor/editor/browser-test.mjs           # copy-editor browser checks (needs nori-browser)

# Need GEMINI_API_KEY; write results into aeo/
python3 tools/grade_page.py [slug ...] > aeo/grades-$(date +%F).jsonl
python3 tools/aeo_probe.py [runs]      > aeo/baseline-$(date +%F).json
python3 tools/overlap.py site/compare/devin.html reference.html
```

Browser tests can attach to an existing session Chrome through `PLAYWRIGHT_CDP_URL`; for example, run `PLAYWRIGHT_CDP_URL=http://127.0.0.1:9222 npm test` from `tests/browser/`. Without the variable, Playwright launches its own browser.

In a Nori Session, background the preview server (`setsid nohup python3 tools/copy-editor/server.py --port 4100 > /tmp/jiro-copy-server.log 2>&1 < /dev/null &`) and open the session's `/port/4100/` URL.

## Landing page

The site uses self-hosted General Sans from Fontshare for sans-serif UI text, with normal weights 400, 500, 600 and 700 and `font-display: swap`. [The main stylesheet](site/css/styles.css) loads `site/fonts/GeneralSans-{weight}.woff2`; [build.py](build.py) emits the matching declarations into [the generated page stylesheet](site/assets/pages.css). JetBrains Mono remains on code, terminal mockups and the existing monospace UI.

The Fontshare license is [GeneralSans-FFL.txt](site/fonts/GeneralSans-FFL.txt); it permits self-hosting but restricts redistribution, including through public repositories. The binaries are gitignored: run `python3 tools/fetch_fonts.py` before previews or browser tests. The script downloads the official Fontshare archive and checks pinned SHA-256 hashes for the font files and license before writing them. Visitors load fonts from this site, with no browser request to a Fontshare CDN. The manual site-deploy workflow runs the same preparation before syncing. When updating the fonts, review the official source and license before updating the hashes in [the fetch script](tools/fetch_fonts.py).

[Typography browser tests](tests/browser/typography.test.mjs) verify actual custom-font rendering on desktop and mobile, font-file loading, standalone and generated pages, and the code-font boundary.

`site/js/main.js` renders the pixel art (`data-px`) every 100 ms and only writes to the DOM when a region's output changes. The HTML ships with still values, and visitors with reduced motion get a still frame of these regions. The hero carousel and the “How it works” tabs have their own controllers. Pricing faces are independent of the pixel-art clock: each gives a brief, staggered blink when first entering view, then remains still. Without IntersectionObserver or with reduced motion, pricing faces remain static.

The “Ditch D*vin” block gives the headline, subline and right-hand artwork generous spacing on desktop and mobile. Its decorative [flat Idle sprite](site/img/jiro-idle-flat.svg) comes from Clifford’s approved `nori-monorepo/docs/design/jiro` brand suite: it shares the no-bite favicon’s geometry, with the canonical coral face color and no grain or shadow. `initDitchJiro` in [site/js/main.js](site/js/main.js) adds `is-awake` on the sprite’s first intersection and disconnects the observer. [site/css/styles.css](site/css/styles.css) supplies a single slow, small bounce, independent of the pixel-art clock. The sprite stays still without JavaScript or IntersectionObserver, and the reduced-motion media query prevents or immediately cancels animation. [Ditch browser tests](tests/browser/ditch-polish.test.mjs) cover responsive spacing, bounded motion, stationary adjacent text and live motion-preference changes.

The “Why Jiro” section (`#why`) presents customer testimonials between the comparison table and feature walkthroughs. Quotes sit side by side on a white surface on desktop and stack in reading order on mobile, using the site typography and muted credits. The section is static, and the existing “Why Jiro” navigation link continues to target it. The wording and attributions for Alex (CTO, Corvus) and Danny (CTO, Miravoice) are preserved from the approved quotes, sourced from their published case studies (https://noriagentic.com/newsletter/2026-05-19-corvus-case-study.html and https://noriagentic.com/newsletter/2026-09-18-miravoice-case-study.html), with the previously approved Nori-to-Jiro naming. Keep one quote per company.

"How it works" (`#features`) contains complete, fictional interface stories in [site/index.html](site/index.html): Priya reporting a CSV filter bug in desktop Slack, Kira replying from her phone and resuming the shared session in a laptop terminal; an overnight Linear issue about paid orders stuck pending leading to a Stripe raw-body fix and Dana’s morning PR approval; and the same incident in a shared thread where Jordan receives the broker’s access-denial message while Rae gets the affected-order count, root cause and fix PR. `@jiro-ops` in the permissions story deliberately names a separate ops agent, matching the frozen RBAC video. [site/js/features.js](site/js/features.js) turns the stories into tabs: a white strip (a “Pause stories”/“Play stories” button, then a “Choose a story” tablist reading “01 Multiplayer”, “02 On-call”, “03 RBAC”, with the hero bar’s green active tab and progress line) over a horizontal `x mandatory` snap track where each story is a full-width tabpanel; inactive panels are `inert` and `aria-hidden`, the active one is focusable so Tab moves from its tab into it. One story shows at a time and the tabs autorotate every 20 seconds. Choosing a tab, swiping the track to another story (detected when the scroll settles on a story other than the selected one), arrow keys, or keyboard (`:focus-visible`) focus on the tabs or a panel hands control to the visitor and stops rotation until they press play; the pause button is excluded from that focus rule so its first press always pauses. Clicking into a story only holds rotation while focus stays in the track, so the focused story is never made inert, and a mouse pointer resting on the track holds it until it leaves. Rotation also holds while `#features` is out of view. A smooth scroll the script starts (autorotate or a tab) is tracked so its settling is never mistaken for a swipe, and if interrupted it is finished back onto the selected story; window resizes only re-align the track when its width changes, ignoring mobile toolbar resizes. Steps are plain, non-interactive text; scroll position still emphasizes the active story’s demo region nearest the viewport center and marks its step with `aria-current="step"`.

Sections keep accessible names without visible eyebrow labels. “How it works” and the FAQ use visually hidden headings; the dialog keeps its “Get early access to Jiro” title. The visually hidden “How it works” heading opens the section, ahead of the tab strip, with no visible header block. The stories follow the carousel order: multiplayer, on-call, then permissions, with demo panels on the right, left, right. Each pairs a white `.ftext` panel with a green, orange or dark-green `.fimg` box laid out as a bento: the colored box sits 28px lower and overlaps the copy panel by 28px (mirrored for on-call), with black edges where it meets the white. Each box carries a large decorative no-bite flat Jiro (`.fimg-art`, hidden from assistive tech): [Happy](site/img/jiro-happy-flat.svg) for multiplayer, [Coding](site/img/jiro-coding-flat.svg) for on-call and [Push back](site/img/jiro-push-back-flat.svg) for permissions, drawn from the same Clifford suite and flat body as the Ditch sprite. Each example groups its heading with a short secondary subline, followed directly by the steps without repeating the summary as body copy; step text has no numeric prefixes, and the story numbers remain. The active step gets a left rule and muted surface. The illustrated interfaces use light surfaces within the colored panels, including the terminal and phone views. The colored panels are square where content fits and grow to keep the complete stories readable. At 900px and below, every story stacks text first, then demo, with the box inset 16px and overlapping 12px and absorbing extra height. Without JavaScript the strip stays hidden and the stories stack as complete static examples; with reduced motion there is no rotation, no pause button and tab switches are instant, and changing the preference updates emphasis immediately. Keep each story's steps and demo regions in matching order. The `.fpanel` class on each demo keeps fictional interface text out of the inline copy editor.

Pricing includes a short free-trial line and modest price typography. Cards turn black on hover; their green button fill completes quickly, and the buttons align at the bottom of each card with consistent spacing. The same buttons continue opening the early-access dialog.

Pricing leads directly into the FAQ and sign-up block across the normal green section gap. The FAQ and sign-up block share a 60/40 desktop grid: white FAQ on the left and a narrower black panel on the right. At 900px and below they stack with the FAQ first. The named `#reserve` sign-up region contains only the orange “Get early access” button, vertically centered on desktop with extra upper space on mobile. The button opens the existing dialog, where visitors enter their name and work email.

The design is drawn at 1440px; the "Responsive" block at the end of `site/css/styles.css` steps down at 1180px, 900px (dropdown menu from `initMenu`, stacked sections, sideways-scrolling compare table) and 420px. The comparison and pricing headings are “How Jiro compares.” and “Pricing”. The comparison columns run jiro.bot, Claude Tag, Devin, Factory, then Cursor Cloud; Jiro retains its bold treatment and hover emphasizes the focused row. Comparison rows have generous padding and a minimum height, growing with wrapped content. Headers, row labels and product cells center their text horizontally and vertically, including the pinned labels on mobile. The entire label column inherits the site’s UI font family. Small decorative crosses mark explicit competitor limitations and usage charges, without changing fact-checked wording or marking neutral capabilities as defects. At the stacking breakpoint, the table expands horizontally to preserve product-column widths, larger type, increased line height and cell padding; narrower pinned row labels leave room to read a complete competitor column even on narrow phones. Mobile header padding keeps the Jiro wordmark inside its column, and at 420px and below the nav call to action narrows to 10px padding because General Sans metrics otherwise overflow the 320px header by a pixel. [Comparison browser tests](tests/browser/compare-polish.test.mjs) check spacing, centered text, the label font and decorative crosses. [Layout browser tests](tests/browser/layout.test.mjs) cover narrow phones through ultrawide desktops, including both sides of the stacking breakpoint, and check page overflow, hero balance, pricing-to-FAQ spacing and table containment.

The hero (`#top`) fills the first screen below the sticky header: `.hero-row` is a grid of copy beside media over a full-width bottom bar (`grid-template-rows: 1fr auto`) with a `min-height` of at least 641px, so it grows rather than clipping its copy on short laptops or with enlarged text. The copy column centers its headline/body/CTA stack vertically. [site/js/hero.js](site/js/hero.js) runs the example carousel (Multiplayer, On-call, RBAC), following the WAI-ARIA APG tabbed carousel: the white `.hero-bar` holds a “Choose an example” tablist whose active entry turns green with a thin black progress line; Left/Right/Home/End move between entries, there is one tab stop and selection follows focus. The carousel autocycles every 40 seconds, long enough for each 20–40s clip to finish. Tapping a bar entry jumps there and restarts the interval from it, tapping the video advances to the next example, keyboard focus inside the bar holds the cycle, and the cycle also holds while `.hero-row` is scrolled out of view. The slide title (top-left) and the “Pause examples”/“Play examples” button (top-right) are quiet overlays on the media; pause stops both the video and the cycle. Inactive panels get `tabindex=-1`. The crossfade is 200ms (off under reduced motion). Reduced motion never cycles; pressing play then plays the video only, and switching reduced motion on while playing pauses the video and cycle (the button reads “Play examples”). At 900px and below the hero stacks copy, media, then the bar, which becomes a compact segmented control.

[site/js/tabcycle.js](site/js/tabcycle.js) (`window.JiroTabCycle(strip, interval, advance, area)`) is the shared timer behind the hero bar and the “How it works” tabs, loaded before both controllers. It advances while not paused, not held (named holds such as keyboard focus, a resting pointer, or “offscreen”, which an IntersectionObserver sets while the optional `area` is out of view; the hero passes `.hero-row`, features passes `#features`) and not in reduced motion, and sets `data-cycling` and `--cycle-ms` on the tablist so CSS can animate the active tab’s `.cycle-progress` line; every restart begins a full interval.

The page uses proximity scroll snapping so the hero and “How it works” lock just under the sticky header with the pause control and tab strip visible. `initHeaderOffset` in [site/js/main.js](site/js/main.js) measures the header into `--header-h` on load and whenever a ResizeObserver sees the header change (window resize where unsupported); `html` uses it as `scroll-padding-top`, so section anchors only need a small `scroll-margin-top`. `.hero-row` and `#features` are the snap targets. At 900px and below vertical snapping is off, because stacked sections run taller than a phone screen and locking would fight reading; the horizontal story track still snaps there. Reduced motion turns vertical snapping off everywhere.

Carousel videos are dropped in without code changes: `site/video/carousel/{oncall,multiplayer,rbac}-{desktop,mobile}.mp4` plus `{name}-poster.jpg`. The script picks the mobile cut at 900px and below (re-picking when the breakpoint is crossed), loads only the active example, and under reduced motion loads nothing until play is pressed. Each clip keeps its full width at its native aspect (5:4 desktop, 4:5 mobile) through container query units on `.hc-stage` (`--clip-h`, `--bleed`): it is bottom-anchored and runs about 44px (24px on mobile) past the panel’s bottom edge under the bar, with white stage filling the space above; a panel wider than the clip’s aspect crops it from the bottom. Keep essential video and poster content clear of the bottom edge. The committed clips are muted H.264 loops with shared posters, rendered from [video/carousel-src/](video/carousel-src/README.md). Their pure-white `#ffffff` stage matches `.hc-stage`, blending the videos and posters into the hero panel without a contrasting rectangle. That source folder documents the scene stories, rendering pipeline and rebuild commands; it is outside `site/` so only the final assets are published.

The retired looping hero video (Jiro hero v25) and its render scripts live on the `video/hero-loop-v1` branch.

The navigation names the feature walkthroughs “How it works”. Every handle in page copy reads exactly “@Jiro” (“Tag @Jiro to start.”), including the meta description, generated pages and `llms-full.txt`; [tests/test_handle.py](tests/test_handle.py) enforces this across page sources and these docs, allowing only `@jiro-ops`. The positioning copy spells out “No token markup. No model lock-in.” The footer links to Nori Agentic, includes its copyright line, and retains the “Get early access” dialog opener without repeating the Pricing and FAQ links.

## Early access

Every "Get early access" link or button opens a pop-up asking for name and work email, which posts to the URL in `<meta name="early-access-endpoint">` (the live HTTP API). Successful submission shows “Check your inbox” in the dialog. Visitors join the list only after clicking the emailed link and pressing "Confirm my spot" (opening the link alone does nothing, so mail scanners can't confirm); they land on `confirmed.html` or `link-expired.html`.

Deploy only by dispatching the GitHub Actions workflows from `main`, after approval: [site](.github/workflows/deploy.yml) and [early-access Lambda](.github/workflows/deploy-early-access.yml). The Lambda workflow updates code only; environment configuration belongs to the CloudFormation stack. Architecture and deployment workflow: [docs.md](docs.md) and [Lambda docs](lambda/early-access/docs.md).
