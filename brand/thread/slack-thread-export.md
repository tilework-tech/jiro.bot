### 2026-09-28 22:37 UTC — Jiro

Yes. So far I've been placing every pixel by hand in Python and writing PNGs with a stdlib encoder, which is fine for sprites but slow for anything photographic. Libraries I know and can use here:  - **Pillow (Python)**: the workhorse. Downscale the original with nearest or box sampling, quantize to a fixed palette, apply ordered or Floyd-Steinberg dithering. This is the fastest way to turn your original screenshot into genuine pixel art without redrawing it. - **Aseprite / LibreSprite**: the real pixel-art editor. Scriptable via Lua and a CLI. Best for layers, animation frames, sprite sheets, and palette management. LibreSprite is the free fork. - **Pyxel**: Python retro game engine with a built-in 16-color palette and image editor. Good if the goal is an actual playable thing. - **pngjs / sharp / jimp (Node)**: raster ops if you prefer the JS side. - **Phaser / PixiJS**: for rendering sprites in a browser, not authoring them.  None are installed on this box yet, but Pillow installs in seconds. If you have a specific library in mind, name it. Otherwise the highest-value next step is Pillow: pixelate the original at 64, 96, and 128 px with a 16-color palette, so the icon is derived from the artwork you already like rather than my redraw of it.
